# How PakkByte works

PakkByte uses a GitHub-first workflow so the work can move between four interchangeable computers without making any one computer the master copy.

- **GitHub is the execution system:** repositories, source, Issues, pull requests, Projects, Actions, releases, packages, pages, and security configuration live here.
- **Notion is the control panel:** project context, cross-project decisions, benefit tracking, reminders, and links point back to the canonical GitHub records.
- **A workstation is replaceable:** start from a clone or Codespace, pull before working, push before switching computers, and recreate local-only configuration from documented instructions.
- **Obsidian is deferred:** private thinking may use a future local knowledge layer, but it does not duplicate GitHub tasks or Notion project status.

The practical rules are kept in the [repository conventions](./docs/operating-system/repository-conventions.md), [workstation recovery guide](./docs/operating-system/workstation-recovery.md), and [canonical homes table](./docs/operating-system/where-does-this-belong.md).

GitHub issues, discussions, and repository content may be public. Never put passwords, tokens, private information, or anything confidential in GitHub or Notion.
